# M2-01 V0.3 | PostgreSQL Repository + Order-level Pegging

## Delivered

- `app/domain/pegging.py`: deterministic order-level attribution across shared inventory, confirmed receipts and planned receipts. Sorting: need date ascending, priority descending, order ID ascending. MAKE planned receipts propagate sales-order attribution to lower-level BOM.
- `app/db/repository.py`: psycopg3 Repository; source data seed upsert, source read-back, atomic requirement run + daily lines + pegging persistence, persisted run read-back, canonical input SHA-256.
- `database/003_v03.sql`: pegging table, consistency constraints, indexes.
- `scripts/db_v03.py`: seed/run/read CLI.
- `tests/test_pegging.py`: deterministic allocation and propagation tests.
- `tests/test_postgres_integration.py`: **requires real disposable PostgreSQL**; skipped unless `TEST_DATABASE_URL` is set.

## Local setup (new database volume)

```bash
docker compose up -d postgres
cd backend
python -m pip install -e '.[test]'
export DATABASE_URL=postgresql://lab:local_demo_only@localhost:5432/industrial_lab
python scripts/db_v03.py seed
python scripts/db_v03.py run
python scripts/db_v03.py read MRP-REPLACE_WITH_RUN_ID
```

To execute integration tests, set `TEST_DATABASE_URL` to a **disposable test database** with `schema.sql` and `003_v03.sql` applied, then `python -m pytest -q`. Integration tests modify seed rows. Never use a production DB.

**Existing PostgreSQL volumes:** Docker entrypoint SQL is executed only on first initialization. Apply `database/003_v03.sql` manually using `psql -f` to existing volumes. Earlier V0.2 volumes may already have `database/seed.sql` inserts; reset a disposable V0.2 demo volume before seeding V0.3 to avoid duplicate confirmed supplies (old SUP-* and new SEED-* IDs).

## Important limitations

1. Repository is callable via CLI and Python; the existing `/api/v1/mrp/multi-order` endpoint remains JSON-backed, not DB-backed. No silent DB fallback.
2. Mock ERP/WMS/MES are still single-process mock routes; independent deployment and adapter auth remain future work.
3. Order-level pegging is **planning attribution**, not WMS reservation. No physical stock reservation is performed.
4. The single-parent BOM constraint from the V0.2 engine remains. General shared components with multiple parents, cross-order lot overproduction attribution, capacity limits and full enterprise MRP are not supported. In particular, when a MAKE component has MOQ/lot rounding, extra planned units are not currently exploded/pegged; only allocated MAKE quantity propagates. Do not use such a case for acceptance until this is addressed.
5. This environment did not provide Docker/PostgreSQL runtime; the DB integration tests are authored but have not been executed here. Python unit tests have been executed.
6. Upsert-based seed is for disposable demonstrations, not an auditable transactional import; seeding again increments source versions.
