# M2-02-03 V0.1 | 库存与在途供应分配深化

## 实现范围
- 新模块 `backend/app/domain/supply_allocation.py`，函数 `plan_supply`。
- 按物料共享库存池；库存=on_hand-reserved-blocked；在途按可用日期进入池，晚到供应不回填早期需求。
- 同日订单分配：优先级降序、销售订单编号升序、需求记录编号升序；日期按升序处理。
- 先用现货、再用已到货供应、最后使用新建计划供应；每条供应保留唯一来源标识及分配数量。
- 计划余量在后续日期继续可用；同一自制计划批次只展开一次完整 BOM，不因未来再次被订单使用而重复展开。
- FG 和 MAKE 版本分别按各自计划释放日选择；记录每条需求的父件、版本、父计划批次、原始订单（如果直接来源于订单）。
- 缺失或重叠有效 BOM 拒绝计算；超过规划期的计划释放拒绝计算。

## Pegging 语义
- `Demand.root_order` 仅对订单直接展开的需求明确；由自制件计划批次产生的下层需求以 `parent_plan` 追溯。
- `Allocation.supply_id` 指向 STOCK、RECEIPT 或 PLAN 批次；通过 PLAN 批次、父件及 BOM 版本可沿图追溯上游。
- MOQ 超额产量不虚构订单归属；其组件需求仍按完整计划批次计算。
- 本版为计划归属，不是 WMS 实物预留或真实采购执行。
