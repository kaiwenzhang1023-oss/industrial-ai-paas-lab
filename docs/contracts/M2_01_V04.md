# M2-01 V0.4 | DB-first API and integration closeout (candidate)

## Delivered
- Database-first API namespace `/api/v1/db` with strict 503 failure on missing PostgreSQL; legacy `/api/v1/mrp/multi-order` remains JSON-backed and must not be used as proof of DB persistence.
- `GET /api/v1/db/health`, `GET /api/v1/db/orders`, `POST /api/v1/db/mrp/runs?as_of=2026-10-29`, `GET /api/v1/db/mrp/runs/{run_id}`.
- Seed upserts avoid incrementing order/inventory versions for unchanged source records.
- MAKE lot surplus is attributed to the triggering order for lower-level BOM explosion, while gross customer pegging stays unchanged. This is attribution only, not actual stock reservation.

## Limits / release gate
- Real PostgreSQL integration is NOT certified unless `TEST_DATABASE_URL` is set and integration tests run against an isolated, initialized database.
- The current `load_snapshot` is not a repeatable-read multi-source snapshot; it is a single database read under default isolation. Source version fencing, concurrent seed/run tests, and BOM effective version selection for multi-order differing dates remain outstanding.
- Root production stock and multi-parent BOM are out of scope. The same material lot surplus attribution is a simplified policy; not a general pegging solver.
- Mock ERP/WMS/MES are independent routes but not separately deployed services.

## Run
`docker compose up -d postgres` from project root (fresh volume); `cd backend && pip install -e ".[test]" && pytest -q`; set `DATABASE_URL=postgresql://lab:local_demo_only@localhost:5432/industrial_lab` and run API. For DB integration tests, initialize an **isolated** test database and set `TEST_DATABASE_URL` explicitly. No silent skip counts as passing.
